# E58 語料結構設計(DRAFT 呈議;2026-08-30)

依 benchmark 需求反推語料配比與題池經濟。判定基準=官方三科唯一裁判。

## 1. Benchmark 需求盤點(A₃ 0.4558 態,對 bf16 錨恢復率)

| 科目 | A₃ 讀數 | bf16 錨 | 恢復率 | 診斷 |
|---|---|---|---|---|
| humaneval | 23.17 | 94.51 | **24.5%** | 最深洞;E57 內容軸定罪=閉合示範是 he 教材(碼全凍 +7.32pp) |
| gsm8k | 50.87 | 95.53 | 53.3% | E38 域餵料 +7.7 成立;列最便宜(~1.4k tok/列) |
| IFEval | 54.71 | 92.79 | 59.0% | 對模板最魯棒(偽模板時代已站穩);但 E52 稀釋稅 −4.25 前科 |
| 終止軸 | stable 空核 40 | — | — | 橫切病灶;v4 真模板主治(探針自然終止 98-100%) |

## 2. 證據 → 結構原則

1. **he 洞最深 + code 教材已定罪** → code 重配(最大 token 份額)。
2. **稀釋稅前科**(E52:code 定向 he +3.05 但 IF −4.25)→ ifshape 保底
   ≥30% token 份額,不許為 code 讓路。
3. **math 高性價比**:列成本 1/4,域餵料證實有效 → 以列數補、token 少配。
4. **agentic R1 缺席、R2 併入**(27B 題池;§5)。
5. **同劑量=同 token**(v4 列長異質:if~5.2k/code~5.8k/math~1.3k 中位;
   cal8/cal10 時代「同列數」比較在 v4 失效)。

## 3. R1 配比提案(80M 有效 token)

| 域 | token 份額 | 列數(≈) | 題池現量 | 用盡率 |
|---|---|---|---|---|
| code | 50%(40M) | ~6,700 | 8,293 | 81% |
| ifshape | 30%(24M) | ~4,400 | 5,796 | 76% |
| math | 20%(16M) | ~11,100 | 11,131 | **~100%** |

→ **R1 靠現有題池剛好跑滿一梯**(三池用盡率 76-100%),R2 起無新題可用。
這是 27B 出題槽先行的定量理由:每梯 80M 需新題 ≈ code 6.7k、if 4.4k、
math 11.1k(共 ~22k 題/梯;300M 追冠軍 ≈ 3-4 梯)。

**替代槓桿:k-rollout**(同題多軌,k=2 題需求減半)。溫 1.0 考場採樣下
軌跡自然分化,KD 合法;風險=E42 math 尾段 dup 飽和前科(那是題面 dup,
非軌跡 dup)——凍結前用 50 題 ×2 軌探針量軌跡間 12-gram 重合率再裁。

## 4. 題池經濟(27B 本機槽 vs API)

- 27B NVFP4 本機:$0;吞吐實測(2026-08-30,思考全開,同 seed 同 prompt):
  無 MTP 單流 55.8 / 8 併發 246.9 / 32 併發 965.2 tok/s;
  **原生 MTP(qwen3_5_mtp,k=2)全檔位勝出:96.0 / 516.6 / 1401.5 tok/s
  (1.72× / 2.09× / 1.45×)→ 生產配置=MTP+32 併發 ≈ 5M tok/h**;
  驗證閘全沿用(code 沙箱+空樁對照 / math 3取2+Python 驗算 /
  if 官方 IFEval 檢查器);跨庫 12-gram 去重種入 20260814+e42 兩代舊庫。
- API 後備:deepseek-v4-flash $0.0013/題 → 22k 題/梯 ≈ $29(額度政策照
  bleachers 綱領;本機吞吐不足時的補位,非主線)。
- GPU 衝突:出題與教師產料共用同卡 → 出題排在產料前的空檔
  (E58 R1 產料 ~10-15h 已用現有題池,期間 27B 槽不必開機;
  R2 題池在 R1 fill/drain 段的 GPU 空檔補產)。

## 5. agentic v4 設計(R2 併入;gen_agentic 待批後實作)

程序驗證可行形:**操作軌跡題**——27B 生成「初始狀態+操作序列+問最終
狀態」型多步任務(檔案系統/字典狀態/表格變換),自解出最終狀態;
驗證=把操作序列翻成 Python 執行比對(判定權在程序,同 math 紀律);
3取2 一致擋歧義題。教師端(A1)以完整 chat template 作答=agentic 軌跡
天然帶工具式分步結構。除汙:與 IFEval/gsm8k/humaneval 除汙表同閘。

## 6. 與斜率基線的可比性(caveat 照實)

R1 相對 cycle-3(0.0013/M 基線)同時改了:模板(偽→真)、列長
(全頂格 16384→自然長 1.3-5.8k)、配比(四科均分→code 重配、agentic
缺席)。斜率讀數歸因於 **v4 bundle 整體**,不可單獨歸因模板;
prereg 的 H_template_multiplier 按此措辭(已如此)。分科增量
(he vs if vs gs)是拆 bundle 的第一判別器。
