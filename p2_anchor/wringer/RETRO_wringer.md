## 1. 目標與鐵則

**北極星(用戶 09-08 定稿)**:IQ2_M 級(~2.7 bpw)純碼帳面下,官方三科 comp ≥ 0.90,並在同帳打贏 GGUF 曲線。
前身是「三元碼單獨 ≥ 0.90」(E62b 後),再前身是「IFEval 恢復帶」與「同域 val CE 完全恢復」。目標一路被證據修正,見 §2。

**鐵則(整條線 69 個實驗共用的紀律)**:
1. **預註冊(prereg)先於點火**:每臂先寫 JSON——問題、判準、falsifier(殺閘)、收卷動作、估時——凍結後才跑;新臂點火要用戶核准。
2. **只認官方裁判**:val CE、KD loss、視窗 loss、區塊重建誤差、碼熵一律 monitor-only,不裁決。這條規則是被 18 筆「代理反轉」打出來的(§4.3)。
3. **falsifier 觸發即封盤,不回問**:ρ < 0.5、he 低於存續線、triage 低於門檻,寫進 prereg 的殺閘一觸發,該軸關閉。
4. **裁決點對齊消費點**:窗態分數不能裁鏈尾、中段分數不能裁最終態(第七、八筆教訓)。
5. **同帳比較**:與 GGUF 比一律用主幹 bpw 內插,不比整模型 bpw、不比不同口徑。
6. **長鏈自動化 + 哨兵**:鏈式腳本 nohup setsid 脫離,預寫哨兵字串與收卷動作,Monitor 盯 log;人只在裁決點介入。

## 2. 白話版:七十個實驗怎麼走到這裡

這條線最有價值的不是最後一個數字,而是**每一次撞牆之後怎麼改方向**。以下按八個階段講,每段只講「當時相信什麼、證據怎麼推翻、於是改成什麼」。

### 第一期(08-05→06,E1–E9):分組風洞——「代理目標會騙人」的第一課
- **當時相信**:三元量化的損失主要來自「哪些權重共用一個尺度」,找到好的分組演算法就能省掉大半損失。
- **證據**:七個分組演算法(幅度、梯度、相關、譜社群……)在代理目標 J 上有勝負,但在 self_attn 上 J 與真實 CE 方向相反;2:4 稀疏在 J 上看起來只差 1.30,真 CE 是 2.55。
- **改成**:E8 放棄代理,直接在「真目標」(Σ 補償的 GPTQ 式重建 + 聯合尺度)上零訓練,gap_closed 從 0.29 跳到 0.64。E9 進一步證明「舊裁決不跨 régime」:換了補償方式,旋轉從 ×1.244 的負債變成 ×0.913 的資產。**教訓:每引入新自由度,先重校代理,再重測裁決。**

### 第二期(08-06,E10–E13):同域 val CE「完全恢復」的幻覺
- **當時相信**:凍碼只訓尺度 α,同域 val CE 能回到 bf16;E13c 的準五元檔位做到 gap_closed 1.001,看起來「完全恢復」。
- **證據**:P2 錨定把同一個模型放到 lm_eval 四科,quinary 相對缺口 gsm8k +98%、humaneval +94%、mmlu +52%、ifeval +39%。同域 val CE 完全不轉移。
- **改成**:裁判從 CE 換成 benchmark;E15 判定「均勻域損傷」,資料多樣性升主修。

### 第三期(08-07→09,E14–E27):LTA 綱領三連敗,檔位階梯意外開路
- **當時相信**:量化後的損失是「容量」問題,加旁路 LoRA、微調 norm、交替重解 T 與 α 應該能補。
- **證據**:LoRA 旁路零增量(E17-lora)、norm 微調四科全退但 val CE 更低(E18)、T↔α 交替重解翻碼 14.5% 四科崩到 0.08–0.10(E19)、逐層特徵 KD 讓 mmlu 隨 λ 單調跌(E23)、課程重排顯著劣化(E24)。
- **意外**:E25 檔位階梯 k∈{3,5,7,9} 零訓練 val CE 2.43→1.86,九元零訓練幾乎等於五元訓練後;E27 全量四科九元新冠軍。
- **改成**:綁定約束從「容量」改為「訊號/表示」;外層重解目標必須是 W_eff 而不是原 W;路線改為「先站上高元起點,再往下降」。

### 第四期(08-09→12,E28–E36):官方裁判上線、三元直攻、「不翻碼」定律
- **當時相信**:逐窗自蒸餾 QAT 可以把三元直接練回來。
- **證據**:E28 官方 IFEval(bf16 90.94)下 QAT 88.54 過恢復帶,但 val CE 方向與官方相反(Corkscrew 流第五筆反轉)。三元直攻 g3 零訓練只有 11.46,滑窗+打磨 27.54,端到端軟打磨 35.49(E31),混合多元 44.55(E32)。五次重現 e2e flip = 0.0000:端到端訓練根本不翻碼,只動連續軸。四科錨定揭露混元損傷極不均勻(mmlu chance-corrected 只有 16.0)。E34 形變降元 9→7 成功(86.51),E35 7→3 單走廊終碼 96.3% 只是靜態投影,E36 全組合淨傷害。
- **改成**:第七、八筆反轉立下「裁決點對齊消費點」;分數主宰權在碼軸,連續軸(α、θ)只能打磨;需要一個能在凍碼下承接功能的容器。

### 第五期(08-13→24,E37–E48):蓄水/排水機制誕生
- **當時相信**(用戶提案 E37):把碼全凍,掛 r128 低秩旁路對 bf16 老師做 KD(蓄水),再把旁路逐窗吸收進碼與尺度(排水)。
- **證據**:E37 A 閘 50.46、B 閘 50.28,排水保留率 ρ 0.969,新冠軍。E38 擴 rank 換語料 A 更高但 ρ 崩到 0.485——**排水吞吐成為新的綁定約束**。E39 老師軌跡 on-manifold 語料 54.90;E40 bleachers 題庫 10× 產料 70.43(+15.5),排空對照 63.03 證明水庫的獨立貢獻 7.4;E41 半 g16 72.27。E42–E47 一路修排水口徑(W_max、分層 calib、去噪 β、γ 場),結論是「排水中不可動水」、「最窄口徑決定吞吐」。E45 起主判改為三科等權回復率(甲/comp):用戶一句「遵守指令+亂寫 code=沒有能力的執行者」廢掉 IFEval 單科制。
- **改成**:蓄水/排水成為主線引擎;排水段被反覆證明是漏水處。

### 第六期(08-24→09-02,E49–E58):閉合軸、語料軸、規模化,以及碼軸的定罪
- **當時相信**:天花板不夠高是語料問題;排水漏水是劑量問題。
- **證據**:O1 稽核發現冠軍 14.2% 回應全空——思考不終止;E51 對 `</think>` 閉合位置加權 KD 封新冠 0.7469。E52 code 閉合語料買 he 賣 IF(語料是分科定向武器);E53 整軌長窗殺閘,語料軸封盤;E54 從頭重建盆地失敗(token 饑荒:42M vs 文獻 10B)。E57/E58 16k 全鏈 + 80M 規模化把 A 閘推到 0.7038,但 ρ 0.748;E58R1b 兩臂再證 **he 保留率隨翻碼量單調下降(.622→.568→.487)**。

### 第七期(09-02→07,E59–E63):碼軸手術——藍圖、旋轉、擴桶、非對稱
- **當時相信**:從九元藍圖直解到三元(E59)、學旋轉載體(E60)、逐模組混合桶 M 承接水(E61/E62)、非對稱三元(E63)其中之一能把三元推到 0.90。
- **證據**:九元零訓練 comp 0.9226 輾壓三元冠軍 0.7388,但 9→3 直解崩到 0.1289(跳出盆地一卻落壞盆地);旋轉載體 val CE 1.690 優於 bf16 2.003,官方 0.0832 等於隨機旋轉(第 13 型反轉);擴桶 ρ 到 0.889 差 0.011;E62b 診斷出 L 是訓練鷹架、M 是真載體;非對稱三元零訓練 +0.054(0.820)。

## 3. Wringer 最終配方(p3b_w)

```
bf16 (Agents-A1-4B)
 ├─ 1. 閉式量化(quantize --grid 8 --block 128 --solver gptq --prior-lam 0.01)
 │     模組表:k_proj/v_proj int8 逐列;o_proj 16 級 g128;
 │             in_proj_z / in_proj_qkv / gate_proj / out_proj 4 級 {-2..1} g128;
 │             其餘(q_proj, up_proj, down_proj)8 級 {-4..3} g128;α int8 + 逐列 fp16 尺度
 │     步驟:alpha_search(雙向符號)→ gptq_grid(全 Σ、OBS、damp 1%、前綴量化 Σ)→ scale_joint(Tikhonov 先驗 λ 0.01)
 │     校準:128 列 × 16k 老師自生軌跡(code 66 / ifshape 33 / math 29)
 │     → p3b:2.655 bpw,comp 0.8144
 ├─ 2. 蓄水(res_fill):碼材化凍結,每個目標 Linear 掛 W + B·A/r(r=128,B 零初始)
 │     KD 老師 = bf16 自身;同一批 128 列 16k;閉合加權 </think> 32 / 後 8 位 16;
 │     3000 步、batch 2、lr 2e-4、grad-ckpt、hidchunk(logits 不整條物化);約 7.5 h
 │     → resA(含水 fp):he 79.88
 ├─ 3. 擰乾(quantize --base-dir resA,同模組表、同先驗):以 W_eff = W_q + BA/r 為目標重新閉式解碼與 α
 │     → p3b_w:帳面仍 2.655,he 84.15
 └─ 4. 官方三科:IF 87.80 / he 84.15 / GS 92.95,comp 0.9365
```

三個設計選擇是這個配方能成立的原因:
1. **留零的偶數格點 + 符號方向位**:八元 {−4..3} 與四級 {−2..1} 各丟一個極值換 α 的符號自由度,g128 把 α 開銷從 0.5 壓到 0.125(fp16)或 0.067(int8)b/w。
2. **全 Σ GPTQ 閉式 + 先驗**:E65-X 之前的閉式解在零空間飄移;λ 0.01 的 Tikhonov 先驗把 dense 差距從 44% 壓回,是所有後續閉式步驟的前提。
3. **水只當鷹架**:E64 證明水可以整體閉式吸收,E69 證明吸收後比含水態更好(B > A)。推論態沒有任何旁路,帳面就是零訓練點的帳面。

## 4. 方法論精華(可複用的部分)

### 4.1 預註冊 + falsifier + 收卷動作
每臂在點火前寫死:問題、判準門檻、殺閘條件、收卷時要跑的儀器與 commit 內容。好處不是形式,而是**當結果出來時沒有解釋空間**——E53、E54、E59、E62a、E65-X 都是 falsifier 一觸發就封盤,省下了至少四條再試一次的支線。

### 4.2 只認官方裁判
18 筆代理反轉(§4.3)之後,規則變成:訓練側任何曲線只能 monitor。代價是每個裁決點要花 1–3 小時跑 vLLM 官方三科;收益是整條線沒有一次「代理說好、官方說壞」被當成進展。

### 4.3 被推翻的假設清單(節選,完整見 HISTORY §c)
| 假設 | 推翻它的證據 |

| 同域 val CE 恢復 = 能力恢復 | P2 錨定四科全 HOLE;E28 val CE 方向反;E60 旋轉載體 CE 優於 bf16 但官方=隨機 |
| 分組演算法是三元損失主因 | E1–E5 三方向全證偽;E8 完整優化自由度才治好 |

### 4.4 「水是鷹架」的思維
早期把旁路當成要「排回去」的東西,排水段的口徑、劑量、節奏做了七個實驗(E42–E47)。E64 之後改成「水只是暫存功能的容器,最後用閉式解一次吸收」,排水節奏軸整個失去對象。這是整條線最大的一次簡化。

### 4.5 同帳對照
沒有 GGUF U 曲線之前,「打贏」沒有定義。E67 之後每個點都對 U 曲線同帳內插,並且發現三元家族其實輸在 α 開銷而非碼——這直接導向 E68 的 g128 帳面對齊。

### 4.6 長鏈自動化與哨兵紀律

## 6. 與文獻的定位
- **ParetoQ**:三元/2-bit QAT 需約 30B token 才飽和;我們的水只用約 1 億 token,靠的是閉式起點夠高與吸收回碼,而不是 QAT 劑量。
- **ScaleQ-1.58(2026-08)、CAT-Q(ICML 2026)**:Qwen3-4B 級三元 PTQ 的 code 保留率上限約 60–70%,與我們三元線的 he 68% 一致;這是我們放棄三元、改走「八元留零 g128 + 部分四級」的外部佐證。
- **GGUF/llama.cpp k-quants、imatrix、Unsloth 動態保護**:我們的 U 曲線就是這一套;同帳 2.655 處內插 0.527,對照我們 0.9365。
- **LLM-QAT / GKD / QA-LoRA / DARE**(見 LIT_reservoir_review.md):蓄水機制的親戚;差別在我們的旁路最後不保留、也不合併進 bf16,而是被閉式解吸收進整數碼與尺度。
